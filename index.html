    Glossary & Architecture Concepts

    Definitions, operational context, and where each concept lives in the Geo SCADA database.

    Server Architecture

    Main / Standby Redundancy

    Two servers hold a synchronised copy of the database. The Main server runs drivers, history, and alarms; the Standby continuously receives updates and takes over automatically if the Main fails or is manually switched.

    Context Standard for critical water and power SCADA. Clients reconnect to whichever server is Main.

    Mapping Configured in the Server Configuration Tool and the Server / Redundancy settings of the database; visible under Server Status.

    Triple Standby

    Adds a third server to the redundancy set so that one failure still leaves a redundant pair. Commonly one server is placed at a remote disaster-recovery site.

    Context Plan bandwidth and latency for the synchronisation link to the third node.

    Permanent Standby

    A standby server that is never promoted to Main automatically. It holds a replicated database (for example at a head office or DR site) and is promoted only by deliberate operator action.

    Context Useful for read-only reporting, backup, and controlled DR failover.

    Listeners

    Network endpoints on the server that accept inbound connections: client connections, and, for drivers such as DNP3, inbound connections from outstations that initiate (dial-in / unsolicited over TCP).

    Context A DNP3 TCP listening channel waits for the RTU to connect; a direct channel makes the connection outbound. Open the matching firewall rule.

    DB Server Ports (5481 TCP)

    The Geo SCADA database server accepts client and tool connections on TCP 5481 by default. Additional ports are used by the web and Virtual ViewX services and by redundancy links, depending on version and configuration.

    Action Allow 5481/TCP from engineering and operator networks only. Check Server Configuration Tool for the exact list in your release, and keep the firewall rule set under agac.ae change control.

    Client Interfaces

    ViewX

    The Windows rich client used for both engineering (configuration, mimic design, queries) and operations (alarms, trends, controls). Access is governed by security roles and permissions.

    Virtual ViewX

    HTML5 web client that renders ViewX-authored mimics, lists, and trends in a browser with no client install. Suited to remote operators and tablets.

    Context Not every ViewX feature is available. Test mimics in Virtual ViewX before declaring them web-ready.

    Example Field technicians view pump station overview mimics and acknowledge alarms from an iPad over the corporate SCADA VPN.

    Original WebX

    The earlier browser client that predates Virtual ViewX. Retained for legacy sites; new work should target Virtual ViewX.

    Database Model

    Hierarchical Database Structure

    Every object lives in a tree rooted at the Root Group. Objects are addressed by their full name, for example AGAC.DXB.WPS01.Pump1.Run. Security, alarm handling, and history inherit down the tree.

    Groups

    Container objects that organise the tree (region, site, plant area). Groups can carry security permissions and are the natural boundary for alarm areas and mimic navigation.

    Group Templates

    A reusable blueprint of a group: points, outstations, logic, and mimics, with substitutable template parameters. Editing the template updates all instances.

    Group Instances

    A concrete group created from a template. Instances inherit all template content and supply values for the template parameters.

    Property Overrides

    Per-instance changes to properties that the template would otherwise control, such as IP address, outstation address, or an alarm limit at one site. Keep overrides to a minimum and document each one.

    Example In Template_PumpingStation the high-level alarm delay is 10 s. In instance WPS_01 only Outstation.DirectHost is overridden to 10.20.5.42; the alarm settings stay tied to the template.

    Protocol Drivers & Telemetry

    DNP3

    Outstation-based telemetry protocol with timestamped events. Object structure: Channel → Outstation → Points (analog in, binary in, counters, analog out, binary out).

    • Class 0: static snapshot of all current values (integrity poll).
    • Class 1 / 2 / 3: event buffers, assigned per point by priority/type.
    • Unsolicited: outstation reports events without being polled; must be enabled on both RTU and the driver.

    Practice Typical: integrity poll every 15–60 min, event poll 5–30 s, unsolicited enabled for Class 1.

    Modbus (RTU, TCP, Register Mapping)

    Master/slave register protocol. RTU is serial; TCP wraps the frame in TCP with a unit ID. Data is read from register tables: coils, discrete inputs, input registers, holding registers.

    Gotcha Many documents use 1-based addresses (40001) while the wire uses 0-based offsets. Confirm the convention for the vendor map and the driver. Check word and byte order for 32-bit floats.

    OPC DA / UA

    Client interfaces to third-party servers. DA is COM/DCOM based and Windows only; UA is cross-platform with built-in security and certificates. Prefer UA for new work.

    MQTT / IoT

    Publish/subscribe messaging for lightweight devices and IoT gateways. Topics map to points. Always use TLS and per-device credentials, and decide a payload format (JSON, Sparkplug B) up front.

    Telemetry & Industrial Protocol Terms

    IIN Bits (Internal Indications)

    A 2-byte bitfield returned by a DNP3 outstation in every response, reporting device state: restart, event buffer overflow, class data available, need time, configuration or parameter errors.

    Context First place to look when an outstation is online but behaving oddly.

    Example After an RTU power cycle it returns IIN1.7 = 1 (Device Restart). The master must react (for example time-sync and clear the restart bit) before the flag drops.

    Class 0, 1, 2, 3 Data

    Class 0 is the static current value of every mapped point. Classes 1, 2 and 3 are timestamped events recorded by the outstation when a point changes. Used to manage bandwidth over telemetry circuits.

    Example A flow transmitter fluctuates every 100 ms during a pump surge. The RTU buffers the timestamped changes locally as Class 3 events, and one event poll retrieves them, preserving the surge shape without high-frequency polling.

    Point assignment Class 1 = critical alarms, Class 2 = high-priority operational events, Class 3 = periodic status and analogs (agac.ae convention).

    Select-Before-Operate (SBO)

    A two-step command: the master sends Select to arm the output, the RTU echoes it, then the master sends Operate inside a short timeout window. Prevents noise or a stray frame from issuing a command.

    Example Opening a 33 kV motorised breaker uses an SBO digital output on DNP3 Group 12. If the echo does not match within the timeout (for example 3 s), the operation is aborted and the operator is alerted.

    WITS (Water Industry Telemetry Standards)

    A DNP3-based profile for water and wastewater telemetry with standardised point configuration, file transfer, and local logging. Geo SCADA offers WITS outstation types within its DNP3 driver.

    Example A remote sewer level monitor using a WITS outstation object for burst telemetry and configuration synchronisation from ViewX. Confirm feature support for your RTU model.

    Data Historization & Alarms

    Historical Logging

    Point values and events are stored in the historian. Define a historic data configuration (logging interval, on-change, or both) and a retention plan sized to disk.

    Trend Objects

    Saved trend definitions (pens, scales, time ranges) that can be opened from a mimic pick action or embedded as a live trend in a display.

    Compression Algorithms

    Reduce stored data by dropping samples that lie within a tolerance of a line between kept samples. Set tolerance from instrument accuracy, not by habit; too wide hides real process movement.

    Example A 0.2 bar deadband on a 0–16 bar pressure transducer ignores pumping vibration between 5.01 and 5.15 bar, but a sudden drop to 4.7 bar writes a historic record immediately.

    Alarm Priorities

    Numeric severity attached to alarm conditions and used to sort, colour, and filter. agac.ae maps categories Critical / High / Medium / Low onto agreed numeric ranges (see Tutorial 4).

    Alarm Redirection

    Routes alarms to alternative destinations (e-mail, SMS, pager, other operator groups) based on area, time, or unacknowledged duration.

    Example A Critical wet-well overflow alarm (AGAC.DXB.WPS01.HighHigh_ALM) left unacknowledged for 300 s triggers an SMS action carrying the alert and station ID to the on-call engineer.

    Event Logging

    Time-ordered journal of state changes, operator actions, and system events. This is the audit trail; do not shorten retention below the contractual requirement.

    Logic & Scripting

    Structured Text (ST)

    IEC 61131-3 text language used for server-side logic such as calculations, interlocks, and sequencing.

    IF Wet_Well_Level > 3.5 AND NOT Duty_Pump_Fault THEN
  Duty_Pump_Start := TRUE;
ELSIF Wet_Well_Level < 1.2 THEN
  Duty_Pump_Start := FALSE;
END_IF;

    Function Block Diagrams (FBD)

    Graphical data-flow language: blocks (timers, comparators, PID) wired together. Good for readable control loops.

    Sequential Function Charts (SFC)

    Step and transition model for sequences such as pump start-up or filter backwash.

    ViewX Client Scripting & Automation

    Client-side scripting on mimics and the automation interface let you drive displays and query the database from external programs. Availability and language depend on the release; check the Geo SCADA help for your version.

    Tutorial 1 · Database Hierarchy & Template Instantiation

    Build the agac.ae tree once, template every standard station, then instantiate with minimal overrides.

    Safety. Perform on the engineering or test database first. Take a database backup before bulk changes. Do not instantiate onto a live production server without change approval.

    Step 1 · Root System Group and asset tagging

    1. In ViewX, open Database Bar → Groups. Under the Root Group, create AGAC as the top-level group.
    2. Create region groups using a 3-letter code, for example DXB, AUH, SHJ.
    3. Under each region create site groups with the format <TYPE><NN>, such as WPS01 (Water Pumping Station) or SSF01 (Substation Feeder).
    4. Use asset names without spaces; use the Description field for human-readable names. Resulting full name: AGAC.DXB.WPS01.Pump1.Run.
    Example tagging convention
    LevelPatternExample
    CompanyAGACAGAC
    Region3 lettersDXB
    SiteTYPE + 2 digitsWPS01
    AssetName + numberPump1
    PointFunctionRun, Fault, Level

    This convention is a suggested standard; align with the agac.ae master asset register before use.

    Step 2 · Create a Group Template for a standard station

    1. Create a template group, for example AGAC.Templates.WPS_Std, and mark it as a template (Group Template).
    2. Inside it, add the outstation, points, logic, and mimic that every pumping station shares.
    3. Define template parameters for anything that differs per site: SiteName, RTU_IP, RTU_Addr, HiLevelLimit.
    4. Bind properties to parameters by referencing the parameter in the property field.

    Step 3 · Point definitions and alarm thresholds

    Template point list
    PointTypeUnits / StatesAlarm
    LevelAnalog Inm, 0–4.0HiHi 3.8 · Hi 3.5 · Lo 1.0
    Pump1.RunDigital InStopped / RunningNone (event only)
    Pump1.FaultDigital InNormal / FaultHigh priority on Fault
    Pump1.StartCmdDigital OutStop / StartControl failure alarm
    CommsFailOutstation statusOK / FailedMedium after 60 s

    Thresholds above are placeholders; apply the values from the process design document.

    Step 4 · Instantiate and apply Property Overrides

    1. Create a group under the site path (for example AGAC.DXB.WPS01) and set its template to WPS_Std.
    2. Fill in the template parameters: RTU_IP = 10.20.30.41, RTU_Addr = 41.
    3. Use a Property Override only when a value cannot be a parameter. Record every override in the site commissioning sheet.
    4. Save. Confirm the instance shows the full point tree.

    Tutorial 2 · Driver Configuration & Outstation Telemetry

    DNP3 and Modbus TCP: channel, outstation, points, scaling.

    Safety. Keep new outstations disabled (or in simulation) until addressing is confirmed. Never enable control points on a live RTU until output blocking is verified.

    Step 1 · Channel object

    1. Under the site group create a driver channel for the protocol (DNP3 Channel or Modbus equivalent).
    2. Set Channel type to TCP/IP. Choose Direct if the server connects out to the RTU, or Listening if the RTU dials in.
    3. Set port: DNP3 20000, Modbus TCP 502.
    4. Set connection timeouts and retry intervals. Starting values: connect timeout 5 s, retry 30 s.
    5. Serial/radio links use handshaking and RTS/CTS settings matched to the modem; TCP does not need them.

    Step 2 · Outstation Sets and Outstations

    1. Create the outstation under the channel. For DNP3 set Outstation address and Master address (agac.ae default master = 1).
    2. Set the IP of the remote endpoint when using a direct channel.
    3. Set poll rates: Class 0 integrity 15 min, Class 1/2/3 event poll 10 s; enable unsolicited if the RTU supports it.
    4. Enable time synchronisation if required and agree one time source for all RTUs.
    5. Group outstations into an Outstation Set when they should share settings or failover paths.
    Channel  : AGAC.DXB.WPS01.Ch1   TCP Direct  port 20000
Outstation: AGAC.DXB.WPS01.RTU   Addr 41  Master 1
Polls    : Integrity 900 s | Event 10 s | Unsolicited ON (Class 1)

    Step 3 · Add AI, DI, AO, DO points

    Point types
    TypeDirectionKey properties
    AI Analog InputRTU → SCADAPoint address, raw range, engineering range, units, deadband
    DI Digital InputRTU → SCADAPoint address, state text, invert, alarm on state
    AO Analog OutputSCADA → RTUEngineering limits, select-before-operate, security level
    DO Digital OutputSCADA → RTUControl model (direct / SBO), pulse time, confirmation point

    For Modbus, map registers per the RTU vendor table:

    Level      Holding reg 40001 (offset 0), INT16,  raw 0-10000  -> 0-4.0 m
Pump1.Run  Coil 00001   (offset 0)
Pump1.Cmd  Coil 00101   (offset 100) write

    Step 4 · Scaling, deadbands and event persistence

    1. Enter raw range (counts the RTU sends) and engineering range (real units). Geo SCADA computes the linear scaling.
    2. Set engineering units text (m, bar, kW) so trends and mimics show them.
    3. Set a deadband of 0.5–1 % of span to avoid noise-driven events; use a smaller one for tight control loops.
    4. Set events and history so important changes are retained: enable event logging for state changes and historic logging with the agreed compression tolerance.
    Eng = EngMin + (Raw - RawMin) * (EngMax - EngMin) / (RawMax - RawMin)
e.g. raw 5000 of 0-10000, eng 0-4.0  ->  2.0 m

    Tutorial 3 · Interactive Mimics & High-Performance HMI

    Quiet gray displays where color means something.

    Safety. Every control on a mimic needs confirmation, a permission level, and a status echo. Test controls only in the simulation database.

    Step 1 · ISA-101 base layout

    1. Create a new mimic under the site group. Set a light-gray background (about RGB 200,200,200, or dark gray in dark rooms) and use it consistently.
    2. Draw equipment in grayscale; use thin outlines and no gradients, shadows, or 3D effects.
    3. Reserve color for abnormal states: red/amber for alarms, one accent for operator-selected items. Add a text or shape cue so color is not the only signal.
    4. Use a four-level display hierarchy: overview, area, equipment detail, diagnostics.

    Step 2 · Animations and pick actions

    1. Select the pump symbol → Animations → Color / Fill. Bind to Pump1.Run: Stopped = light gray, Running = dark gray.
    2. Add a Fault animation: show a red outline and a visible text badge.
    3. For the tank, add a Size / Scale animation on height bound to Level with the engineering range as min/max.
    4. Add Pick Actions: left-click shows the context menu (Start, Stop, Trend, Details); double-click opens the point display.
    5. Place a Trend pick action that opens the saved trend object for the point.

    Try the behavior in the Mimic / Point Preview.

    Step 3 · Embedded trends, alarm banner, health indicators

    1. Insert a Trend control and bind pens to Level and Pump1.Run, with a one-hour default range.
    2. Insert an alarm banner/list control at the top of every display, filtered to the user's area.
    3. Add a system health indicator bound to CommsFail and the server status so loss of data is obvious.

    Tutorial 4 · Alarm Prioritization, Redirection & Event Actions

    Fewer, better alarms, delivered to the right person.

    Safety. Suppression hides real conditions. Always time-limit it, record who applied it, and make suppressed states visible on the mimic.

    Step 1 · Categories and priorities

    Alarm categories
    CategoryPriority rangeResponseExample
    Critical1–100Immediate, escalate in 5 minWet well HiHi level
    High101–400Within 15 minPump fault
    Medium401–700Within shiftComms fail
    Low701–999PlannedDoor open

    Ranges are an agac.ae example; adapt to the alarm philosophy document. Check which direction your version treats as most severe.

    Step 2 · Escalation and redirection

    1. Define alarm categories and areas under the Alarm settings of the root group.
    2. Create redirection rules: Critical → on-call e-mail + SMS immediately; if unacknowledged after 5 min → supervisor group.
    3. Configure the e-mail/SMS gateway in the server and test with a dummy point.
    4. Set an operator-handover timer for shift changes so alarms always have an owner.

    Step 3 · Suppression during commissioning

    1. Add a Maintenance digital point per site and bind alarm inhibit to it.
    2. When set, alarms from that site are inhibited but still logged to the event journal.
    3. Show a clear MAINTENANCE banner on the site mimic while active.
    4. Clear the flag at handover and confirm alarms return.

    Tutorial 5 · Commissioning, Diagnostics & Server Status

    Prove the signal path from field to screen.

    Safety. Coordinate with plant operations. Use simulated or forced inputs only under permit, and restore every forced value afterward.

    Step 1 · Server Status

    1. Open Server Status from the ViewX System menu or the Server Configuration Tool.
    2. Check database size and growth, historian state, and redundancy synchronisation.
    3. Review the driver list for channels and outstations that are offline.
    4. Review client sessions to confirm who is connected and from where.

    Step 2 · Driver comms logging

    1. On the channel or outstation, enable protocol logging to a file at the lowest level that answers the question.
    2. Reproduce the fault, then disable logging; logs grow quickly.
    3. Read frames: link-layer address, function code, object group/variation, and IIN bits for DNP3.
    4. For deeper issues capture on the network with a packet analyser (for example Wireshark on a mirrored port) and compare with driver logs.
    Symptom                         Likely cause
No response                      wrong IP/port, firewall, wrong outstation addr
Responses, no points             wrong object group/variation or point index
Values off by 10x/1000x          scaling raw/eng range mismatch
Intermittent timeouts            poll too fast, radio/bandwidth, retries too low
Events missing                   unsolicited disabled or event class unassigned

    Step 3 · End-to-end telemetry loop test

    1. Field: inject a known value (for example 4, 12, 20 mA for 0/50/100 %).
    2. RTU: confirm the register or point shows the value.
    3. Server: confirm the raw and scaled value in the point details.
    4. HMI: confirm the mimic, trend, and alarm limits respond.
    5. Control: with the plant isolated, issue a command and confirm the RTU output and status feedback.
    6. Record results on the loop sheet; restore all test conditions.

    DNP3 Implementation Guide

    Geo SCADA DNP3 uses a four-tier hierarchy: Channel → Outstation Set → Outstation → Points.

    Verify menus. Menu paths below follow the agac.ae ViewX screenshots. Entries differ between releases, so confirm against your installed version.
    Safety. Leave the outstation and any control points out of service until addressing is confirmed. Do not test output points on live plant without a permit.

    Object tree

    AGAC (System Group)
 └── DXB
      └── WPS01
           ├── DNP3_Direct_Channel        [DNP3 -> Direct Channel]
           ├── DNP3_Direct_OutstationSet  [DNP3 -> Direct Outstation Set]
           ├── RTU01_Outstation           [DNP3 -> Generic/SCADAPack -> Direct Outstation]
           ├── P1_Run_DI                  [DNP3 -> Binary Input Point]
           ├── WetWell_Level_AI           [DNP3 -> Analog Input Point]
           └── P1_StartStop_DO            [DNP3 -> Binary Output Point / Pulse]

    Step 1 · Create the DNP3 Direct Channel

    1. In ViewX right-click the station group (for example AGAC.DXB.WPS01).
    2. Select Create New → DNP3 → Direct Channel.
    3. Open the channel configuration:
      • Connection Type: Network (TCP/IP) or Serial.
      • TCP/IP: Direct (Geo SCADA initiates) or Listening (RTU initiates).
      • Port: default 20000.
      • Timeouts: Connect Timeout 5 s, Retry Delay 30 s.
    4. Tick In Service and save.

    Verify The channel icon in the Database Bar shows no red cross or warning badge.

    Step 2 · Create the Outstation Set

    1. Right-click the group → Create New → DNP3 → Direct Outstation Set.
    2. On the Outstation Set tab choose the Channel from Step 1; Protocol: DNP3.
    3. Save and set In Service.

    Step 3 · Create the Outstation (RTU node)

    1. Right-click the group → Create New → DNP3 → Generic → Direct Outstation (or SCADAPack E / WITS for dedicated hardware).
    2. Outstation tab:
      • Outstation Set: the set from Step 2.
      • Address: RTU link-layer address (e.g. 11).
      • Local Address (Master): 1 (agac.ae standard).
      • Direct Host: RTU IP (e.g. 192.168.1.50) and TCP port 20000.
    3. Scan Parameters tab:
      • Integrity Poll (Class 0,1,2,3): 15M routine, 1H for low-bandwidth cellular.
      • Event Poll (Class 1,2,3): 5S or 10S.
      • Unsolicited Messages: enable for GPRS/cellular RTUs that report events without waiting for polls.
    4. Save and set In Service.

    Verify Right-click the outstation → Retrieve Diagnostics, or read the comms status: it should show Healthy / Online. Check the IIN bits if it does not.

    Step 4 · Add and map DNP3 points

    Right-click → Create New → DNP3 → …

    DNP3 point types
    Point typeMenu selectionObject group / variationTypical use
    Binary InputDNP3 → Binary Input PointGroup 1 (Var 1/2)Pump run/stop, trip, door open
    Binary OutputDNP3 → Binary Output Point or Pulse (Trip-Close)Group 12 (CROB)Start/stop, breaker trip/close
    Analog InputDNP3 → Analog Input PointGroup 30 (Var 1/2/4)Level, pressure, flow
    Analog OutputDNP3 → Analog Output PointGroup 41VSD speed setpoint (Hz)
    CounterDNP3 → Counter PointGroup 20 / 21Volume totaliser (m³)

    On each point's DNP3 tab:

    • Link the Outstation from Step 3.
    • Enter the Point Number (DNP3 index starts at 0).
    • Select the Event Class: Class 1 = critical alarms, Class 2 = high-priority operational events, Class 3 = periodic status and analogs.

    Procedure 6 · Logic Engine (Structured Text & SFC)

    Automated calculations, pump interlocks, and scheduled routines using IEC 61131-3 logic inside Geo SCADA.

    Safety. Develop and test logic that writes to outputs on the simulation database first. Server logic must never be the only protection for plant; hardwired and RTU-level interlocks remain primary.

    Steps

    1. Under the site group choose Create New → Logic → ST Program (Structured Text).
    2. Map database points into the program variables: 
      PROGRAM WetWell_LeadLag
VAR
    Level      AT %M(.WetWell_Level_AI.CurrentValue) : REAL;
    Pump1_Run  AT %M(.P1_Run_DI.CurrentValue)        : BOOL;
    Pump1_Start AT %M(.P1_StartStop_DO.Value)        : BOOL;
END_VAR

IF Level >= 3.8 AND NOT Pump1_Run THEN
    Pump1_Start := TRUE;
ELSIF Level <= 1.2 AND Pump1_Run THEN
    Pump1_Start := FALSE;
END_IF;
END_PROGRAM
    3. Compile and confirm Compile Status: OK.
    4. Set Execution Mode to On Point Change or Periodic (10 s).

    The variable-binding syntax shown follows the agac.ae example; check the Geo SCADA logic help for the exact address syntax in your release. Add hysteresis between start and stop levels, as above, to prevent pump cycling.

    Procedure 7 · Historical Configuration, Archiving & Maintenance

    Prevent database bloat and keep trends fast.

    Steps

    1. Open the analog point and go to the Historic tab.
    2. Enable Historic Data.
    3. Configure compression: Significant Change (e.g. 0.05 m for a level sensor); smaller changes are not recorded. Set Historic Lifetime (e.g. 2 Years).
    4. In the Server Configuration Tool, check the Historic → Archive Volume path and retention schedule so the partition cannot fill and stall the server.
    Choose significant change from instrument accuracy and process dynamics. Confirm retention against contract and audit requirements before setting a lifetime.

    Verification

    Procedure 8 · User Security, Roles & Permissions

    Secure ViewX and Virtual ViewX following industrial cybersecurity practice.

    Safety. Keep a second administrator session open while changing permissions so you cannot lock yourself out. Never share accounts.

    Steps

    1. In the System folder create user groups: Engineers, Shift_Operators, Read_Only_Viewers.
    2. Set explicit permissions on each database branch:
      • Operators: View, Confirm Alarms, Control Points.
      • Engineers: Configure, Delete, Force Points, Edit Logic.
      • Read-only viewers: View only.
    3. Enable Action Confirmation: require password re-entry or two-step verification for high-risk remote controls such as opening a high-voltage feeder.
